# 群内交流与顾问场景审查

## 可重复执行验证

先启动开发服务，随后运行 `pwsh -File scripts/test-communication-advisor.ps1`。脚本通过 Vue 开发代理访问真实身份服务和两个群组服务，并启动仅监听本机的模拟模型；结束时停止模拟模型。每次创建独立测试账号并留下明确标记的讨论，便于检查持久化数据。

| 使用场景 | 验证证据 | 结果 |
| --- | --- | --- |
| A 发布问题，B 回复，A 阅读回复 | 两个真实账号与群组 API 往返 | 通过 |
| 同一账号加入两组后跨组读取讨论 ID | 第二组对第一组讨论 ID 返回 404 | 通过 |
| 保存自定义模型地址后发起咨询 | 身份服务访问本地模型 HTTP 接口 | 通过 |
| 继续追问依赖前文 | 模拟模型确认请求包含上一轮 assistant 消息 | 通过 |
| 同组另一成员查看我的顾问历史 | 返回空列表 | 通过 |
| 同一账号切换组查看顾问历史 | 返回该组自己的空历史 | 通过 |
| 未加入群组读取顾问历史 | 返回 403 | 通过 |
| 清空我的历史 | 再次读取返回空列表 | 通过 |
| 未配置密钥、模型限流、成员资格失效 | AdvisorTest 中的 HTTP 模拟与权限断言 | 通过 |
| 密钥留空保留配置、资料接口不回传密钥 | IdentityIntegrationTest | 通过 |
| 群组节点凭证跨组使用、撤销后继续读取 | test-group-isolation.ps1 | 通过 |

## 审查判断

帖子加回复适合算法问答和复盘。后台逐次核验成员资格，讨论和回复同步事件原子落库。页面每 30 秒刷新讨论与已展开的回复，因此属于定时同步交流，不能称为即时聊天。成员撤销后服务端会拒绝新请求。

私人顾问会话按账号和群组隔离，不能自动广播给群友。模型调用前，用户需确认共享当前讨论和自己的最近会话；失败时不追加虚假的成功记录。模型生成后再核验成员权限。顾问目前是只读上下文咨询，不执行用户代码、不自动发布讨论。

模型请求期间用户修改输入时，回答必须匹配发出时的问题，保留用户后来输入的草稿。群组切换和退出登录清空可见上下文，旧请求结果通过群组版本校验丢弃。

## 尚不能证明的项目

公网 NAT 穿透或中继尚未实现，本机双服务测试不能代替跨网络验收。浏览器自动化初始化失败，尚未取得实际点击操作和视觉布局的验收证据。用户已明确将在之后自行填入供应商配置，当前不测试真实模型回答质量。超时、并发会话请求、历史清空与进行中请求的竞争仍需补齐验证。整体目标保持进行中。
