# 将群组部署到另一台电脑

普通用户可以申请创建群组；管理员批准后，创建者决定部署在中心主机还是自己的另一台 Windows 电脑。公开群组仍需账号登录，但无需群组密钥；私密群组由创建者分享加入密钥。

## 中心主机准备

保持社区服务、公网中继、网关及公网隧道运行，在管理后台开启公网访问。临时 HTTPS 地址记录于本机 `data/public-processes.json`。

本次更新正在运行的旧 Java 服务可能占用文件。请在**最初启动服务的终端**，进入项目目录运行 `update-project.cmd`。它会停止旧公网及本地服务，安装已生成的更新包并重启本地社区。完成后运行 `start-public.cmd` 开启公网隧道。此过程不会删除数据库。

如果没有本机已生成的更新包，更新脚本会调用 Maven 构建后端，需要 Java 21 以上、Maven、Node.js 和已安装的前端依赖。已生成的更新包位于被 Git 忽略的 `data/pending-update`。

## 创建者操作

1. 在“群组入口”申请创建公开或私密群组，等待审批。
2. 打开右上角用户菜单 → “消息与申请”。
3. 点击“部署到其他电脑”。系统为该群组生成独立的连接凭证，并自动注册中继，然后下载 ZIP 部署包。
4. 把 ZIP 放到目标 Windows 电脑，解压到固定目录。需要 Java 21 或以上，双击 `start.cmd`。不需要安装 pwsh 或开放路由器端口。
5. 返回“消息与申请”，刷新查看在线状态，再点击“打开群组”。群组页面的讨论、成员、节点、顾问入口均通过该群组中继访问。
6. 私密群组创建者在“消息与申请”或群组邀请管理中查看加入密钥，只分享加入密钥给成员。

部署包只包含该群组的连接凭证、加入密钥、账号验证公钥和运行程序，不包含中心身份签名私钥或 MySQL 账号。**不要分享整个部署包或 group-config.json。**

系统无法直接安装软件到浏览器所在电脑；目标电脑须运行一次部署包。之后连接端会自动持续向公网中继发起 HTTPS 请求。

## 数据和停机

远程群组这一版使用独立的 H2 文件数据库，位于部署目录 `data/group*`，重启可保留讨论和成员。中心主机仍使用既有 MySQL。远程主机并未自动安装 MySQL，也不代表多台主机共同写入同一个数据库。

在部署目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\stop.ps1
```

停止后备份 `data` 文件夹。保留部署目录，再次运行 `start.cmd` 即可恢复。默认本地端口为 8180、8181，单台电脑暂支持一个这样的部署实例；不要在两台电脑同时运行同一个部署包。

## 公网地址变化和异常

Cloudflare 临时隧道重启可能变更地址。创建者在中心服务重新开放公网后，点击“重新下载部署包”，停止远程群组，替换 `group-config.json` 再启动。保留旧 `data` 文件夹。

- “中继服务未运行”：中心主机先运行 `start-public.cmd`。
- “中继注册失败”：确认中心主机已安装此次更新并重启公网服务。
- “已注册中继，等待远程主机”：部署包已生成，尚未检测到远程连接。
- “远程主机离线”：检查两台电脑是否休眠、公网开关是否开启、配置地址是否过期。
- 目标端口被占用：先停止旧部署实例，避免重复启动。
- 启动失败：查看部署目录 `data/group.log`、`data/group.err.log`、`data/tunnel.log`、`data/tunnel.err.log`。

注册信息会保留在中心主机 `data/remote-relay-registry.json`，中继重启后恢复，不再需要手工写入群组列表。注册接口仅供内部管理调用，不通过公网网关公开。
