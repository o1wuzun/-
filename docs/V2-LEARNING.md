# 第二版：群组学习工作台

## 使用流程

1. 普通用户在群组入口申请公开或私密群组，管理员审批后由申请人部署。申请人是该群组组长。第一版的两个示例群组没有配置组长，保留历史学习点功能；阶段计划请先在自己创建的群组中测试。
2. 组长进入“学习”，发布阶段计划，填写阶段、截止日期、变更说明及任务。任务可使用 Codeforces 题号，也可填写其他学习内容；自动 OJ 验证目前只支持 Codeforces。
   组长也可以先在群组“概览”卡片中点击“进入计划设定”；系统会自动跳转到学习页的计划编辑区。已有计划进入时默认编辑下一版本，首次发布则打开空白计划表单。
3. 成员确认加入指定版本，设置自己的每日学习时间，领取任务。计划更新发布为新版本，已领取任务保留原题目、检查标准、截止日期与计划版本。
4. 点击“继续学习”进入任务详情。总结、学习时间和证据说明自动保存草稿；也可手动保存。正式提交后生成独立历史记录。离开详情可回到学习总览。
5. 延期、换题、申请跳过均要填写原因。跳过须组长审批。延期不会自动标为失败；周复盘分别统计按时完成、延期完成和本周到期未完成。
6. 正式提交后填写检查点回答，可补充变式题说明。组长从“组长待处理”给出检查反馈；未通过进入“待补充”，可重新正式提交或补充回答复测。历次提交、回答、评价、申诉与调整历史保留。换题或重新正式提交后，旧的待检查标记为“已被后续调整替代”；只有当前题目的最新正式提交可以继续检查或申诉。
7. 可以发起 AI 辅助检查。先在个人设置填写模型地址、名称及密钥，再勾选当前任务的上下文授权。AI 提供检查建议，最终检查由组长反馈，系统不自动宣称知识掌握。可记录对 AI 的异议，并通过检查点申诉请求人工复核。
8. 绑定本组的 Codeforces 用户名后，从正式提交记录点击“同步 Codeforces 验证”。仅匹配该任务题号、绑定账号、上海时区提交当日的 AC；填写提交编号或总结本身不会标记验证通过。用户名关联不等于账号所有权证明。
9. OJ、AI 检查在后台处理。可离开页面再回来查看结果；失败或服务重启显示“检查暂不可用”，允许重试，不将学习判为失败。同一检查处理中禁止重复创建。
10. 检查未通过的任务进入私人复习队列，记录理解与下次复习日期，可查看复习历史。默认不公开；“主动分享”仅向本组成员公开任务、题目和错题原因，不公开私人总结、回答或复习全文，可随时撤回分享；再次检查失败产生新原因时会自动撤回分享，需本人重新选择公开。
11. 从任务发起求助，只公开你主动填写的提问；解决后回填理解并保留任务关联。阶段复盘可保存卡点、下阶段计划与确认状态。

## 页面与隔离

群组左栏固定为“概览、学习、交流、资料、成员”。交流内含私信快捷入口，成员内含同步节点及组长权限管理。Agent 是右下角辅助入口，默认收起，显示“当前检索范围：本群组”。

顶部群组选择器切换群组及阶段。概览的“继续学习”“待补充”会进入相应任务，“到期复习”进入学习页复习队列。切换前等待当前打卡草稿保存；有版本冲突时不会覆盖较新草稿，并可恢复本窗口未同步内容供核对。草稿缓存按用户、群组、任务分别保存。旧请求使用创建时绑定的群组地址，不能被后来切换的群组重定向。

学习总览顺序为“今日待办 → 需要处理 → 当前阶段进度 → 学习记录与复盘”。任务旁说明建议原因。任务详情采用主内容与辅助侧栏，包含状态、期限、检查点、证据、组内资料及可展开 Agent。第一版学习点、积分、打卡历史在折叠区保留。

首页可只读展示各组进度，离线或无权限群组不会计入。不合并不同组的完成状态。计划支持显式复制到其他群组，要求源群组成员及目标群组组长权限；只复制计划内容，不复制任务执行、草稿、提交、检查或复习状态。复制后独立发布、修改。

## 开发与运行

- 群组服务 `/api/v1/group/study` 提供计划、任务、检查点、复习、求助、复盘、资料与成员管理接口。
- 身份服务 `/api/v1/study-jobs` 提供异步检查创建、按群组读取结果、异议记录。后台队列有容量限制；重启时未完成任务转为可重试的暂不可用，不把用户令牌写入数据库。
- `/api/v1/study-overview` 提供只读跨组汇总，`POST /copy-plan` 复制计划；上下游均再次校验成员或组长权限。
- 群组数据库保留物理隔离，新增表同时以服务端配置的 `group_id` 作为主键范围，所有私人查询附带用户条件。私人学习记录与私信不进入群组复制日志；主动公开的求助正文作为普通讨论进入复制日志。普通成员的私人答案仅在提交组长检查后进入组长待办；Agent 默认只能读取调用者本人记录。
- H2 启动脚本自动创建新增表；MySQL Flyway 群组 V4/V5、身份 V9 迁移新增结构，不删除历史数据。已部署群组在恢复过程中逐个迁移。数据库备份与 H2 导入工具已包含新增表。
- 第一版便携 EXE 仍是第一版，尚未重新生成第二版安装包。源码运行使用原有 `start-community.cmd`；请先停止第一版桌面程序，避免端口冲突。

## 验证入口

后端：`mvn "-Dmaven.repo.local=F:/social/.m2build/repository" -pl services/identity-service,services/group-service,services/database-tools -am test`。

前端构建：`npm --prefix frontend run build`。浏览器：为当前终端设置 `TEST_ADMIN_EMAIL`、`TEST_ADMIN_PASSWORD` 后运行 `npm --prefix frontend run test:e2e`，用于审批测试群组；不要把真实密码写入脚本或提交仓库。

新增后端测试覆盖计划快照、版本冲突、私有及跨组读取、延期换题与跳过审批、检查补交与申诉、OJ 独立证据、外部失败保留原状态、复习分享撤回、求助回填、成员权限、异步检查去重/重启/隐私。浏览器流程覆盖真实 MySQL 群组部署、草稿切换、检查与 AI 重试、复制计划独立性、资料发布、首页汇总及桌面/移动布局。

最终验收记录见 [V2-IMPLEMENTATION.md](V2-IMPLEMENTATION.md)，包含测试范围、结果及运行限制。
