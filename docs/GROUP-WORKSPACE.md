# 群组工作区与数据归属

每个群组具有独立页面地址 `#/groups/{id}/{page}`，页面可选择 `home`、`learning`、`discussion`、`group-messages`、`advisor`、`members`、`nodes`。群组左栏不展示社区或管理功能；“退出群组界面”只返回入口，不撤销成员资格。账户设置、系统消息由头像菜单进入。

## 学习任务

新数据存储在群组服务自己的数据库。新增表 `oj_bindings`、`learning_points`、`daily_checkins`、`learning_awards`、`learning_plans`。群组服务验证登录签名及当前成员资格，仅允许读取或修改自己的记录。群主和其他成员不能通过学习 API 读取他人的目标。

学习 API 为 `/api/v1/group/learning` 下的 `overview`、`oj-binding`、`points`、`checkins`、`checkins/{id}/verify`、`checkins/{id}/settle`、`plans`。

打卡唯一性为成员、日期、学习任务。每次打卡结算 1 分；每道题在该群组第一次验证 AC 额外 2 分。重复结算不会重复发分，多项任务引用同一题也不会重复获得该题奖励。修改群组内 OJ 绑定将使尚未结算的验证证据失效。

旧中心身份库中的个人记录继续保留，只提供历史查看入口，不自动导入任意群组。远程部署群组因此持有自己的学习数据；模型密钥继续仅位于身份服务，规划时身份服务携带用户登录凭证从受信群组地址读取历史，生成后再次确认成员权限。模型服务仅获得当前组自己的学习记录。

## 回复对象和成员消息

讨论评论增加 `reply_to_user_id`、`parent_comment_id`。回复评论时父评论必须属于当前讨论，指定收件人必须匹配原作者且仍是本群组成员；普通评论默认指定讨论作者。`/api/v1/group/replies/me` 按收件人查找，避免参与过讨论便收到后续所有消息。

独立成员消息存储在 `member_messages`，通过 `POST /api/v1/group/messages`、`GET /api/v1/group/messages/me`、`PATCH /api/v1/group/messages/{id}/read` 发送、查询、标记已读。仅双方可查询，只有收件人可标记已读。成员消息和个人学习数据不写入可复制的讨论事件日志。

## 数据升级和验证

群组 MySQL 新增 Flyway V2、V3，H2 在启动时添加相应表和评论字段。已有本地部署群组由中心部署器迁移；已经在其他电脑运行的部署包需要下载更新程序，停止后替换程序并保留 `data` 数据库目录。数据库备份工具已包含新表。

已验证：多任务同日打卡、重复结算和题目奖励去重、跨群组和跨成员隔离、撤销成员后禁止读取、规划只用当前群组历史、定向回复对象验证、成员消息隐私、实际 MySQL 升级，以及桌面/手机浏览器的导航、消息、公式、顾问会话和多群组学习切换。
