# 算法同行使用手册（Spring Boot + Vue 3）

本手册对应当前 Spring/Vue 版本，入口端口是 **5173**。README 后半部分中的 8000 端口属于旧 Python 原型。

## 1. 谁需要安装项目

选一台电脑作为主机服务器，运行前端、身份服务、各群组服务和数据库。其他成员的电脑、手机只需浏览器，不需要安装 Java、MySQL 或复制项目。

目前“一键部署本地群组”是在**服务器电脑**创建独立群组进程和数据库，不是在点击按钮的成员电脑安装服务。主机必须保持开机、联网；休眠或停止程序后，成员无法连接。普通浏览器访问不会把数据库复制到成员电脑。

## 2. 先在服务器电脑测试

当前电脑已有构建和本地 MySQL 配置。在 PowerShell 7 中执行：

```powershell
Set-Location 'F:\社区'
pwsh -File .\scripts\start-private.ps1 -Database mysql
```

这个命令会关闭本项目的公网连接和现有开发进程，再重新启动本机服务。等待服务就绪后打开：

```text
http://127.0.0.1:5173/
```

如果已正常启动，无需重复执行。第一次复制到其他服务器时，需准备 Java 21 或以上、Maven、Node.js 和 PowerShell 7，并按 [MySQL 说明](MYSQL.md) 初始化该机器的项目数据库，构建后才能启动。不要把旧机器的运行进程记录当作安装配置。

## 3. 开启局域网访问

### 服务器启动

在服务器电脑执行：

```powershell
Set-Location 'F:\社区'
pwsh -File .\scripts\start-private.ps1 -BindAddress 0.0.0.0 -Database mysql
```

`0.0.0.0` 表示监听本机网络接口，不是成员应打开的网址。这里使用这个值以同时保留本机接口，供前端代理连接后台服务；当前脚本不建议改成仅绑定某一个具体网卡 IP。

此模式不启动公网隧道，也不需要路由器端口转发。当前开发启动脚本还会使两个固定后台服务监听网络接口；成员访问统一走 5173，无需另开后台或数据库端口。动态创建的群组继续只监听服务器本机。

### 查找地址

在服务器电脑执行 `ipconfig`，找到正在使用的 Wi-Fi 或以太网网卡的 IPv4 地址。不要选择 WSL、虚拟机、代理软件的虚拟网卡地址。

2026-10-11 检查时，本机 WLAN 地址为 **10.166.234.192**，因此同一局域网成员应打开：

```text
http://10.166.234.192:5173/
```

地址可能在重连 Wi-Fi 后改变，以届时实际地址为准。成员电脑上的 `127.0.0.1` 指向成员自己的电脑，不能用于访问服务器。

### Windows 防火墙

如果服务器自己能打开页面，而其他设备打不开，可在 Windows 防火墙允许 **TCP 5173** 入站。仅允许本地子网即可，不必给成员开放 MySQL 3307、身份服务 8081 或群组后台端口。

也可以在服务器的**管理员 PowerShell**中创建规则：

```powershell
New-NetFirewallRule -DisplayName '算法同行局域网访问' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 5173 -RemoteAddress LocalSubnet -Profile Private
```

这条规则适用于 Windows 标记为“专用”的可信局域网。若当前是学校、公司或访客网络的“公用”配置，规则不会生效；遵循该网络要求配置，不要直接关闭防火墙。项目不会自动修改网络配置或防火墙。

服务器与成员设备需在可互访的网络。访客 Wi-Fi、校园网或路由器开启客户端隔离时，即使连接同名 Wi-Fi，也可能互相访问不了。

## 4. 注册、加入和创建群组

1. 成员打开服务器网址，点击右上角“登录 / 注册”，建立个人账号。
2. 在“群组入口”选择群组。公开群组需要登录，但不需要加入密钥；私密群组需要群主提供的加入密钥。
3. 输入设备名称并进入群组。群组首页、讨论、成员和同步节点都属于当前群组。
4. 成员可在讨论页发布问题和回复，联网成员页显示成员状态。浏览器约每 30 秒发送心跳，90 秒无心跳后显示离线；这表示网页连接状态，不证明成员电脑已经关闭。

创建新群组：

1. 普通用户点击“＋ 创建群组”，填写名称、简介，选择公开或私密，提交申请。
2. 管理员在“管理后台”批准或驳回。只有管理员账号显示后台入口；普通账号不能通过前端把自己设为管理员。
3. 申请人点击头像左侧消息图标，或从用户名菜单进入“消息与申请”，查看审批回复。
4. 批准后申请人点击“一键部署本地群组”，等待实际部署完成。
5. 回到群组入口刷新目录。私密群组申请人可在自己的申请旁查看加入密钥，再发给需要加入的成员。

原有两个演示群组也是私密群组。维护者可在服务器本机的 `data/dev-keys.json` 中读取 `join_key` 或 `contest_join_key` 字段，仅分享对应群组加入密钥；**不要把整个文件发给成员**，文件还包含身份签名私钥。

详细部署、恢复与新增群组备份范围见 [本地群组部署说明](LOCAL-GROUP-DEPLOYMENT.md)。

## 5. 消息、个人设置和顾问

- 头像左侧“消息快捷入口”：查看系统审批消息及当前群组中与你相关的讨论回复，点击回复跳到讨论。
- 点击用户名：“个人设置”修改昵称、头像、密码和服务连接；“消息与申请”查看完整消息与申请。
- 右下角“顾问”：弹出快速提问窗口。群组问答需要先加入群组；明日学习规划不需要先加入群组。
- 顾问需要在个人设置中填写模型接口完整地址、模型名称、API 密钥。接口通常采用兼容的 `/v1/chat/completions` 地址；具体地址和模型名称以服务商提供的为准。发送上下文前需勾选确认。

模型调用发生在服务器电脑。若模型服务也运行在服务器电脑上，设置中的 `http://127.0.0.1:...` 指服务器电脑，不是正在操作网页的成员电脑。

审批反馈主要查看应用内消息；SMTP 邮件设置不是局域网浏览器使用的前提。

## 6. 每日学习、OJ 验证和结算

1. 点击侧栏“每日学习”，绑定 Codeforces 用户名。当前打卡验证仅支持 Codeforces，不需要 OJ API 密钥。
2. 添加学习点：知识目标、Codeforces 题号（例如 `4A`）、理解检查标准。
3. 学习后提交实际分钟和复盘，每天一个账号只能提交一条打卡，日期按上海时间计算。
4. 点击“读取 OJ 验证”。系统在服务器端查询绑定用户名的官方提交记录，检查题号、当日日期与 AC 结果。
5. 点击“结算本日”：打卡基础 1 分，同题第一次取得当日 AC 证据额外 2 分。未验证不能结算；完成读取但没有匹配 AC，可领取基础分。

**结算后记录锁定，不能再补领该日 AC 奖励。** 如果提交仍在判题，先等结果并重新验证，再结算。OJ 暂时不可用时保留记录并提示重试，不能当作验证通过。

点击“根据打卡规划明日目标”，确认将个人最近 7 次打卡发给已配置模型。生成计划后点击“保存为明日目标”；在每日学习页刷新可看到已保存内容。规划 skill 使用历史投入、复盘和 OJ 证据生成建议，不自动改变打卡或积分。

当前用户名绑定只关联公开账号，未验证账号所有权；AC 证据不等于知识掌握，理解检查仍需自检。详情见 [每日学习说明](DAILY-LEARNING.md)。

局域网内的登录、讨论和查看本地记录不要求互联网；Codeforces 验证和远程模型调用要求**服务器电脑**能访问对应外部服务。

## 7. 常见问题

| 现象 | 检查或处理 |
| --- | --- |
| 本机可以访问，成员打不开 | 确认用局域网模式启动、地址正确、防火墙允许 5173、路由器未隔离客户端。 |
| 页面打开，但提示身份或群组服务不可用 | 查看服务器 `data/identity.out.log`、`data/group.out.log`、`data/web.err.log`；服务可能仍在启动。不要把包含凭据的配置文件公开上传。 |
| 原来能访问，现在打不开 | 检查主机是否休眠、地址是否变更、服务是否停止。 |
| 获批后看不到群组 | 先在“消息与申请”完成部署，等待成功，再刷新群组目录。审批通过不等于部署完成。 |
| 创建后“本地部署”没有发生在自己的电脑 | 当前“本地”是服务器本地，客户端独立 PC 安装包尚未提供。 |
| 群组成员状态没有立即变化 | 等待心跳更新；网页关闭后的离线显示有约 90 秒延迟。 |
| OJ 没验证通过 | 检查用户名、题号、提交日期及 AC 状态；无网络或平台失败时稍后重试。 |
| 浏览器刷新后需要重新登录 | 当前登录保存在会话存储中；关闭浏览器会话后需重新登录。 |

## 8. 停止和重启

停止社区服务：

```powershell
Set-Location 'F:\社区'
pwsh -File .\scripts\stop-dev.ps1
```

这个命令停止社区进程，不删除 MySQL 数据，也不停止独立运行的 MySQL 或消息队列。恢复时重新执行第 3 节的局域网启动命令；已经部署的群组会逐步恢复，等待就绪后访问。

不要删除 `data` 目录来“重置启动”：其中保存数据库配置、密钥、部署信息等。公网使用是另一条部署流程，见 [公网中继说明](REVERSE-TUNNEL.md)，与本手册的局域网访问分开。
