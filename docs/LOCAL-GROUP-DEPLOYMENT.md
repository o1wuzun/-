# 用户一键部署本地群组

运行 `scripts/start-dev.ps1` 启用本机部署器。用户在右上角消息入口打开“我的群组创建申请”，管理员批准后，由申请人点击“一键部署本地群组”。此处“本地”指运行身份服务的主机，浏览器不会直接在访问者的电脑启动进程。

后台先将申请置为 DEPLOYING；部署器创建独立 MySQL 数据库和仅具有该库 DML 权限的账号，执行群组 Flyway 迁移，再调用 `scripts/deploy-local-group.ps1` 启动独立群组 JVM。检查 `/api/v1/group` 的响应身份匹配后，才标为 DEPLOYED 并加入群组目录。前端动态代理支持新群组，无需重启前端。点击群组入口会重新加载目录。

用户只能部署自己的已批准申请。待审批、驳回或重复部署会拒绝。失败显示 FAILED 和通用错误提示，申请人可重试；重试复用已创建的数据库和配置，避免覆盖群组数据。旧版仅改状态的假部署记录由 V6 重置为未部署。

部署成功会在原审批通知中追加部署完成说明，重新标记未读并通过应用内 MQ 分发；重启恢复不会重复追加通知。

公开群组允许登录用户无需密钥加入；私密群组检查加入密钥。私密群组申请人可以在自己的申请旁查看加入密钥，其他用户和公开目录无法读取密钥。当前使用共享加入密钥，尚未实现单次邀请、过期和自动轮换。原有两个演示群组仍保留私密加入模式。

新群组分配 8100–8199 端口，仅监听 127.0.0.1。配置、密码、加入密钥、进程记录和日志在 Git 忽略的 `data/deployed-groups` 中。申请输入通过 JSON 传递，名称和简介不插入脚本命令。独立 JVM 只有身份公钥与自己的数据库账号，不需要身份私钥或数据库 root 凭据。

当前身份服务中的本机部署器使用项目 MySQL 配置中的管理员凭据进行建库。因此仅在可信主机开发环境启用；普通独立身份服务默认关闭，可通过 `DEPLOYMENT_LOCAL_ENABLED=true` 启用，`DEPLOYMENT_LOCAL_SHELL` 指定 PowerShell 7 路径。本阶段并非部署到任意客户端或远程主机，也不自动开放公网端口。

停止开发服务会停止同项目群组 JVM。重新启动身份服务后，已部署群组重新检查并恢复启动，数据库数据保留。可选机器人顾问读取动态群组服务的成员权限与讨论；节点接口仍由各群组实例提供。

测试：在进程环境设置本机测试管理员 `TEST_ADMIN_EMAIL`、`TEST_ADMIN_PASSWORD`，执行 `scripts/test-local-deployment.ps1`。该脚本实际创建公开、私密两个群组，并验证审批前拒绝、目录注册、动态代理、加入和讨论写入。

群组配置和新建群组数据库应一起备份。现有 database-tools 会备份身份库中的部署注册记录，但原配置中的固定数据库清单不自动包含新增群组数据库；新增群组数据需另外做 MySQL 备份。部署失败不自动删除数据库，以保留已有内容。
